# 2026-10-12 图片服务启用与验收

4 GB 云主机已启用图片 API，与独立统计服务共同运行。当前配置适合低频调用：单任务并发、每分钟 30 次全局渲染额度，每个任务使用独立子进程，生成完成后退出，回收全部原生内存。

服务地址为 `https://eynnzerr.cloud/blue-fish`，面向所有安装肥鱼工坊 AstrBot 插件的 QQ Bot，默认无需 API Key。插件使用此地址并将 API Key 留空。图片服务包含当前镜像的 257 张素材和 4 种字体。

## 内存与耗时

持续生成目录时，常驻原生渲染进程出现了内存累积，并在早期压力测试中触发 512 MiB 容器上限和一次容器 OOM。显式释放、垃圾回收和分配器调整未形成稳定平台，因此将原生绘图移至短命子进程。HTTP 主进程只负责目录元数据、鉴权、限流和收发 PNG。

| 最终隔离方案的测量项 | 结果 |
| --- | --- |
| 系统识别的物理内存总量 | 约 3.4 GiB，云实例规格为 4 GB |
| 连续资源采样 | 210 秒 |
| 图片容器峰值，含所有渲染子进程 | 213.3 MiB / 512 MiB 上限 |
| 主机最低可用内存 | 2,696.5 MiB |
| 图片容器 swap | 0 |
| 内存上限触发、OOM | 均为 0 |
| 内存与 I/O PSI full avg10 | 采样期间均为 0 |
| 单张成图平均耗时 | 约 0.76 秒 |
| 8 张工坊目录平均耗时 | 约 1.08 秒 |

耗时包含从开发机通过 SSH 隧道请求、创建子进程、注册字体、绘制编码和传回 PNG。短命进程带来启动开销，换取每次任务完成后的确定性内存回收。测试基线中，AstrBot 容器已不在服务器运行列表中。

## 功能与保护验证

- 37 项 HTTP/PNG 检查通过，覆盖 4 种字体、底图格式、透明与白色背景、文字叠加、1/3/8 张目录、鉴权、参数错误与正文大小限制；PNG 在开发机解码检查。
- 额外负载测试成功完成 71 次，其中 35 次为 8 张工坊目录；8 个同时请求中 1 个成功、7 个返回 `503`，并发请求不进入等待队列。
- 全局额度耗尽时返回 `429 RATE_LIMITED` 和 `Retry-After`，额度窗口重置后继续成功生成。
- 图片入口全局 4 个连接、每 IP 2 个连接的限制均经过占位请求验证；超限时返回 `503`，统计接口仍返回 `200`。公网 IP 频率限制返回 `429`。
- 暂停一个测试渲染子进程后，20 秒任务超时将其终止，接口于约 20.12 秒返回 `504 RENDER_TIMEOUT`；统计继续正常响应，随后图片请求恢复成功。
- 图片接口可生成 1024 × 1024 PNG。统计接口保留访问 5 次、导出 2 次的原有计数；两个服务保持健康状态。

### 公共插件接入

- 通过真实 HTTP 连续完成 24 次公共制图，第 25 次返回 `429`；同一窗口随后完成 6 次有效凭证制图，总量达到 30 次后，公共与凭证调用均返回 `429`。配额检查覆盖实际 PNG 生成。
- 上述单图配额测试中，图片容器峰值约 91.1 MiB，主机可用内存最低约 2,806.1 MiB，未触发内存上限或 OOM。
- 本机安装的客户端已更新为支持空密钥的版本。将插件配置设为公共地址、API Key 留空后，通过 AstrBot WebChat 验证字体查询、素材目录和按编号制图，三项均通过。该路径不使用私密凭证。
- 图片与报告保存在本机 `.preview/public-bot-api-20261012/`。公共字体接口与独立统计接口均返回 `200`，两个容器健康。

## 当前保护配置

图片容器限制为 512 MiB 内存、640 MiB 内存与 swap 合计、1 个 CPU、128 个进程或线程；主进程与子进程的 JavaScript 老生代堆各限制为 96 MiB。渲染子进程最长运行 20 秒，超时强制终止，输出最大 8 MiB。

图片入口每个 IP 每分钟 20 次请求，额外突发 3 次；全服务每分钟 30 次渲染，公共调用最多占 24 次，为维护或已授权实例的有效凭证调用保留 6 次。凭证调用也可使用尚未消耗的其余额度，所有调用共享 1 个渲染并发。请求 JSON 最大 8 KiB，文案最多 200 个字符，成图固定 1024 × 1024，目录最多 8 张，只接受内置素材 ID。

云端启用 `ALLOW_ANONYMOUS_RENDER=true`，公共额度由 `PUBLIC_RATE_LIMIT_PER_MINUTE=24` 配置。原生运行和普通自建部署的公共调用开关默认为 `false`。

Nginx 的 `map` 允许空 Authorization，非空错误凭证在读取正文、计算连接数和速率限制之前返回 `401`。调用者的 Authorization 原样转发给后端再次校验，Nginx 不注入服务端密钥或身份标记。默认插件配置不含共享密钥；单独凭证只保存在服务器和已获授权实例的私密配置中。

Nginx 正文读取间隔超时为 10 秒，连接上游超时为 3 秒，发送请求超时为 10 秒，读取响应超时为 30 秒。统计服务使用独立路由和限流额度。

## 运维

配置源为 `deploy/compose.cloud.yaml`、`deploy/nginx-blue-fish-http.conf` 和 `deploy/nginx-blue-fish-locations.conf`。服务器运行目录为 `/opt/blue-fish-studio`，服务代码通过 `server/` 只读挂载，两个进程使用持久化 `data/stats.sqlite`。

原配置、服务代码和 SQLite 在线备份位于 `/opt/blue-fish-studio/backups/image-api-enable-20261012-175326/`。公共服务配置已部署，更改前的备份位于 `/opt/blue-fish-studio/backups/public-bot-api-20261012-210020/`。图片容器采用 `unless-stopped` 策略。需要单独停用图片服务时，在运行目录执行 `docker compose --env-file .env.api stop api`，统计服务继续运行。

详细调用方式见[接口文档](api.md)，更新与回滚配置见[云服务器部署](cloud-deployment.md)。
